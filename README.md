현재 개발중인 서비스의 전체 아키텍처를 전달하면

아키텍처 내 각 구성요소의 CVE를 기반으로 어떤 취약점이 존재하는지 알려줌.

그리고 각 취약점에서 어떤 공격기법(Technique)이 사용되었고,
각 공격기법은 어떤 것인지,
어떤 전략을 위해 사용된 것인지(Tactics),
이를 완화하기 위한 mitigation은 어떤것이 있는지 설명해줌.

+ 현재 아키텍처 구조와 유사한 구조를 대상으로 실제 공격 사례를 보여줌
+ 어떻게 공격이 진행되었고, 어떻게 막아야 했는지도 알려줌



[제약사항]
RAG 기반 도메인 지식 서비스를 개발해야 함
일종의 오픈북 시험처럼 답하게 함
- 우리는 MITRE ATT&CK 프레임워크를 활용

[해주길 원하는 것]
1. MITRE ATT&CK 프레임워크에 관련 API가 존재하는지 확인
2. CVE 정보를 스크랩하는 API가 존재하는지 확인
3. 이를 통해 본 시스템을 어떻게 구성할지 설계
 - 비용 측면에서도 고려해야함
 - 토큰량이 한정되어 있음
4. 혹시라도 저작권관련 확인해야 함
5. 현재 설계되어있는 아키텍처에 대해 보안 점검을 진행해주는 프로젝트를 계획하고 있으나, 서비스를 설명하면 그에 적합한 인프라 아키텍처를 제공하는 것도 가능한지 확인
 - 근거를 댈 수 있어야 함


[직접 해야할 지점]
1. 청킹
- 비유 : 책을 통째로 주지 않고 필요한 쪽만 복사해 줌
- 데이터 길이 분포를 재고 정함

2. 임베딩
- 비유 : 문장마다 의미의 좌표를 찍는다
- 모델 - 바꾸면 색인을 전부 다시 만든다

3. 벡터 검색
- 비유 : 도서관 서가 - 비슷한 주제가 가까이 꽂혀 있다
- 몇 개(Top-k)를 꺼낼지, 한문서 쏠림 대책

4. 근거 기반 생성
- 비유 : 각주가 달린 보고서를 쓴다
- 근거를 못 찾았을 때 어떻게 답할지
